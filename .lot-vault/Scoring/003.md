Read the spec and the current implementation. Today only the prompt's *target* skill scores, once, when the whole prompt is completed (+2 unhinted / +1 hinted), and mistakes are counted per prompt. The spec instead wants per-skill-occurrence scoring, applied immediately — in "a cad ebb" the two a's score the "a" skill twice, etc.

Plan:

1. **Learnt threshold**: "reaches a score of 10" → `isLearntScore` becomes `score >= 10` (currently `> 10`).
2. **Per-occurrence immediate scoring** in `keystroke()`, keyed off the prompt text's translation units (each unit already knows its print span; I'll expose its skill ids too):
   - When the correctly-typed prefix crosses a unit's end (first time only per prompt), every skill in that unit scores: **+2** if no mistake on that unit and the hint wasn't visible yet, otherwise **+1** — so "at least 1 point every time you type the skill", +1 extra before the hint, and a single corrected mistype drops you to 1 point.
   - A mistake event (divergence, as today) is attributed to the unit at the caret. The **second** mistake on the same unit costs its skills **1 point** immediately (floored at 0) and force-shows the hint — same "slip twice" rule as today, but per occurrence instead of per prompt.
   - Indicator skills (capitals, number sign) ride along with their unit and score too.
   - qbf challenge unchanged: never scores.
3. Prompt state gains per-unit mistake/award tracking (replacing `mistakesInARow`); serialization updated tolerantly so existing saves still load.
4. Update tests (including one encoding the "a cad ebb" example) and the architecture doc.

Working on a branch in a git worktree; will merge to main when done.
