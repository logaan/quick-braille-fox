Found the issue: TutorStore.handleInput (src/state/store.ts) feeds the raw input value straight into the core matcher. VoiceOver braille screen input commits a trailing space after each word, so at the end of a prompt the value becomes 'word ' — not a prefix of the expected text — which counts as a mistake (and would instantly fail a qbf run). A stray space can also land on the next prompt if it arrives as its own event after completion.

Plan: normalize in handleInput — strip trailing spaces when doing so turns a non-matching value back into a prefix of the expected text (covers prompt-final spaces, stray spaces on a fresh prompt, and qbf), leave genuinely-expected mid-prompt spaces and real mistakes alone. Adding tests. Working in a worktree; will merge to main when done.
