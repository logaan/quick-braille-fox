Done, on branch `worktree-skill-timers-per-skill`.

## The cause

Two things, both stemming from the hint being tracked *per prompt* rather than
per sign:

1. **Chained reveal timers.** Once the hint appeared, the store uncovered one
   sign of the caret word immediately and then one more every 1000ms on a
   chain of `setTimeout`s that ran whether or not you typed anything. Sign 2's
   clock started when sign 1 was *revealed*.
2. **A single `hintShown` boolean.** Scoring asked "has the hint appeared in
   this prompt?", so the moment any one sign was hinted, every remaining sign
   dropped to +1 — even ones you then typed instantly.

## The fix

Hints are now per skill occurrence, and each sign's countdown starts **when the
caret reaches it** — i.e. when the sign before it has been typed.

- `Prompt.hintShown: boolean` → `Prompt.hintedUnits: Set<number>`.
- Scoring (`unitTypedClean` in `types.ts`) is per occurrence: a sign scores +2
  if it had no mistakes and *its own* hint had not been revealed. Ten minutes
  on one sign costs that sign's bonus and nothing else.
- New core `nextHintFor(state)` names the sign on the clock — always the one at
  the caret — and its wait. The store runs exactly one timer from it and
  re-arms only when the caret moves to a different sign, so revealing a hint
  never starts the next sign's clock; typing does.
- A caret on a space has no countdown at all (a space unit bears no skill), so
  the first sign of a word starts its clock only once the space before it is
  typed — the second thing you asked for, and it falls out of the same rule.
- Waits are unchanged: 400 + 300×score ms for the first sign hinted in a
  prompt, 1000ms for each sign after that.
- The store's `hintUnitsRevealed` / `hintRevealKey` / `hintRevealTimer`
  bookkeeping is gone — reveal state lives in the core now, so it also survives
  a page reload, which it previously didn't.

## Verified

`./scripts/test.sh` — 1651 pass (updated the tests that encoded the old
chaining, added coverage for the new rule). `./scripts/typecheck.sh` and
`./scripts/build.sh` clean.

Also drove the real app in headless Chrome on a seeded "the dog" prompt:

| scenario | observed |
| --- | --- |
| idle 12s on the first sign | `⠮` only — never grows |
| caret parked on the space, 12s | hint area stays empty |
| space typed | `⠙` uncovers at 1016ms, its own cooldown |
| parked on "d" for 8s | still just `⠙` — "o" stays covered |
| "d" typed | `⠙⠕` at 1017ms |

That fourth row is the bug you reported; before this change "o" would have
uncovered a second after "d" did, without you typing anything.
