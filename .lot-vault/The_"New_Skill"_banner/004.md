Removed the banner. Merged to main as `898a7c7`.

## Why it should not stay

**Your point 1 — the random timing is a real bug.** The banner fired the
first time a skill was a prompt's `targetSkillId`. But a skill starts being
*used* in prompt text — and scoring points — the moment it enters the 5-skill
active window, because prompt generation draws on `learnt ∪ active`. Being
picked as the *target* is a separate, random event that happens much later.
So "l" entered the window, showed up in words, earned you 5 points, and only
then got randomly selected as a target and announced as "New skill".

The same mismatch is there from the very first prompt: skills a–e are all
active and all appearing in words, but only whichever one happens to be the
target gets a banner. The other four are silently in use. The banner never
actually marked "this is new to you" — it marked "this is the first time the
RNG aimed a prompt at this", which is not a thing you care about.

**Your point 2 — it is redundant.** The "Learning now" panel already shows
all five active skills, permanently, with braille cells, print form, and
score bar. The banner was a one-prompt flash of a subset of information that
is on screen the whole time. The only thing it added was the group name
("letters", "wordsigns", …), which is not worth a modal-ish banner.

I did consider fixing the trigger instead — introduce on first *exposure*
rather than first target. But done correctly that means showing five intro
banners on prompt 1, which is exactly what the "Learning now" panel is for.

## What changed

Deleted `NewSkillIntro` and its call site (`src/ui/drill.ts`), `IntroView` /
`intro` from the view model (`src/state/view.ts`), `markIntroduction()` and
the `introduced` set (`src/state/store.ts`), `introducedSkillIds` from the
persisted envelope (`src/state/persistence.ts`), the `.intro*` rules
(`src/ui/styles.css`), and updated `docs/ARCHITECTURE.md` with the reasoning.

No storage version bump — the loader ignores unknown fields, so envelopes
written by the old version still load; the stale `introducedSkillIds` is
simply dropped on the next save.
