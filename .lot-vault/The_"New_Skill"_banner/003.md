Found the cause of the "random" timing.

The banner fires from `markIntroduction()` in `src/state/store.ts`: it shows
the first time a skill is a prompt's **targetSkillId**. But a skill is *used*
in prompt text — and scores points — as soon as it enters the 5-skill active
window (`knownSkillIds` = learnt + active, in `src/core/prompts.ts`), which
happens well before it is ever randomly picked as the target.

So "l" entered the active window, appeared in words, earned you 5 points, and
only later got randomly selected as a target — at which point it was announced
as "New skill". The trigger is first-target, not first-exposure.

Same mismatch at session start: skills a–e are all active from prompt 1, but
only the one that happens to be the target gets a banner. The other four are
silently in use.

Checking whether it is fixable-and-worth-keeping vs redundant.
