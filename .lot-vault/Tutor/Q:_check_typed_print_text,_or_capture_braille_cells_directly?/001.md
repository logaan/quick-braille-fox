# Q: check typed print text, or capture braille cells directly?

When typing with macOS VoiceOver's virtual braille keyboard (braille screen input), the OS translates the braille the user enters into ordinary text characters before the web page ever sees it. So the app can only check the *print text* that arrives in the input field.

**Assumption I'm proceeding with:** the learner is shown a print sentence/word, types it using the braille keyboard (or a regular keyboard), and the app compares the resulting print text against the expected text. All *displayed* answers and hints are rendered as braille cells (Unicode braille patterns), as you specified.

Is that right, or did you want the app to capture/score the actual braille cell input somehow (e.g. six-key entry on the regular keyboard with f/d/s/j/k/l as dots)?
