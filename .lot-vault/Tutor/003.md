Starting work. Plan:

**Architecture** (Vite + TypeScript + React-without-JSX via `e = createElement` + Immutable.js):

- `scripts/generate-skills.mjs` — parses the liblouis tables in `data/` into `src/data/skills.json`: grade 1 letters/numbers/punctuation first, then grade 2 contractions/abbreviations in a pedagogically ordered curriculum.
- `src/core/` — pure, Immutable.js-based logic: skill scores, the 5-active-skill scheduler, revision selection (half random / half lowest-score), hint-delay timing, answer checking, score rules (+2 before hint; -only after two consecutive mistakes).
- `src/state/` — app state + localStorage persistence + user interaction handling.
- `src/ui/` — presentation only: braille cell rendering, prompt/input views, responsive layout (laptop/tablet/phone).

**Execution**: I'm coordinating; three subagents will do the implementation sequentially in a git worktree:
1. Scaffold + data pipeline (table parsing → skill definitions + curriculum order)
2. Core logic engine + tests
3. UI, state/persistence, integration, build verification

**Assumptions I'm proceeding with** (each filed as a question Thing under this one):
- The learner types with VoiceOver's braille screen input, which emits ordinary text characters — so answers are checked as print text, while all *displayed* answers/hints are shown as braille cells.
- Hint delay grows linearly with score: `400ms + 300ms × score`, and for learnt skills (score > 10) the answer only appears after two consecutive mistakes.
- Grade 2 curriculum order: alphabetic wordsigns → strong contractions → strong wordsigns/groupsigns → lower signs → initial/final-letter groupsigns → shortforms.
- Practice sentences come from a built-in corpus, filtered so they only exercise skills that are learnt or currently being taught.
