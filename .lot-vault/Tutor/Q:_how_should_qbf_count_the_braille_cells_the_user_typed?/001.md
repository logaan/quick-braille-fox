# Q: how should qbf count the braille cells the user typed?

For the qbf challenge badge I need to count how many braille cells the user typed. The browser never sees braille cells — VoiceOver's braille screen input translates them and inserts *print text* into the field.

**Assumption I'm proceeding with:** count one cell per input insertion event. A regular keystroke inserts one character per event (= one cell, grade 1 style), while VoiceOver braille input commits each cell/contraction as its own insertion, so a contraction like "the" arriving as a single multi-character insertion counts as one cell. Spaces count as cells on both sides of the comparison (typed and theoretical minimum), so the percentage stays fair.

Does that match how your VoiceOver setup delivers input? If it inserts a whole word at a time regardless of cells typed, the count will be wrong and we may need a different measurement (or to drop spaces / count differently).
